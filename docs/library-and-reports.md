# My Library, discovery and weekly reports

Phase D connects the existing shadowing player to a calm next visit: Continue Watching on Home, `/library` for prepared lessons and a watch-later queue, and a seven-day report on `/progress`. Authentic media and the existing listen / pause / repeat loop stay central.

## Library and queue

The library joins the existing eight recent lessons, available transcripts referenced by learner history, account lesson references and up to 60 deliberately saved lesson IDs. It stores references, never another transcript copy. Completed filters use the existing exact transcript revision, so a changed transcript does not inherit completion. Public account lesson references retain the existing trusted restore flow; personal media still asks for reattachment when required. The UI distinguishes locally cached saved-word counts from a complete account dictionary count.

`library:data` contains version 1, `pinned` IDs and at most 40 queue links. Queue links are HTTP(S), have no embedded credentials, are at most 2,000 characters and are validated again on read. YouTube links normalize to video identity to prevent tracking-query duplicates. Learners can remove or move items earlier. Preparing an item returns to the existing Home preparation form with its URL populated; it does not silently acquire media or consume provider work. The queue is deliberately local and scoped to the active account when signed in. It is not synced, included in anonymous-history import, or sent to a recommendation model. Browser storage failure uses the existing in-memory fallback.

## Recommendations and confidence

Find my next lesson combines complete locally prepared transcripts with `/api/discovery`, which exposes up to 12 full validated public Japanese YouTube provider-caption transcripts already in the trusted Cloudflare shared content store. User imports, private media, links with playback secrets and sparse/truncated caption samples are excluded by the server trust boundary. Difficulty artifacts must match the complete caption/section hashes and current generator version. Official YouTube oEmbed supplies actual titles; unavailable titles cause candidates to be omitted. A standard Next.js server without the Worker repository returns an empty public index and local prepared lessons remain useful.

The browser runs the Phase B local morphology and explicit global word states over complete transcripts. With fewer than five word-state records it abstains immediately, without loading the optional morphology dictionary. Candidate work is bounded to 20 lessons, 500 sections and 20,000 characters per lesson. Longer lessons are omitted from this compact discovery pass rather than analyzed as an incomplete sample. Partial morphology output is also omitted. It never uploads word knowledge or personal transcripts to a recommendation model. A locally prepared revision wins an ID collision with the public index; matching difficulty is validated again against that precise transcript.

Fit abstains until a transcript has at least ten distinct content lemmas and five explicit state records. Known lexical coverage counts occurrences marked Known; Learning and unmarked words remain unfamiliar and Ignored words are excluded by the Phase B denominator. Comfortable means at least 90% Known; Stretch means 75–89%; Hard means below 75%. These are product heuristics, not validated listening or ability scores. A Comfortable candidate above the learner's existing recent practised content range becomes Stretch; the reason shows the content estimate and explicit vocabulary evidence. No recent content baseline is invented before the existing five-lesson threshold. State/account changes and unmount invalidate in-flight calculations.

Selecting a recommendation saves its complete lesson and validated matching difficulty, then opens the existing player. The public creator starter links are discovery prompts with **fit unknown until prepared**; availability and usable Japanese captions are checked through normal preparation, with the existing transcript-import fallback. These links do not pretend to be a licensed catalogue. Link references were checked on 6 October 2026 through creator-owned pages: [Nihongo-Learning's park episode](https://podcasts.apple.com/us/podcast/comprehensible-japanese-lets-learn-japanese-in-the/id1615691224?i=1000558456647), [Comprehensible Japanese's short video](https://www.youtube.com/watch?v=wwTl0SrnqTo).

## Weekly evidence and daily goal

The report covers today and the six preceding **UTC practice days**, matching the existing `activeByDay` persistence. The label is explicit; no local-time conversion of historical UTC buckets is implied. Active time includes retained archive daily totals. Section counts include distinct sections explicitly replayed or recorded in detailed practice sessions started and updated inside the period. Archived section counters cannot be dated reliably and are excluded. The UI says Sections revisited rather than claiming to know how many unrecorded spoken repetitions occurred.

Saved terms are new entries currently visible in the bounded device dictionary cache, which can be a partial account view. Marked Known counts current explicit Known states updated in the period and does not claim durable acquisition. Average Shadowing Match uses retained compact Phase C attempt events in the period, not an overwritten latest-section score, and describes recognizer text/timing rather than phonetic quality.

`review:history` retains up to 2,000 idempotent local self-grade events, keyed by review operation ID, only after the current card revision was accepted by the local scheduler. Review recall is Good/Easy answers divided by all self-rated answers. It includes durable pending answers and states their pending count; a network conflict does not erase the fact that the learner chose an answer, but the existing remote schedule still wins. Historical grades are not backfilled from intervals or repetitions. This is recorded self-rating evidence, not a retention prediction. The history follows account storage ownership and remains local.

An optional daily minutes goal lives at `goal:daily`, version 1, with `minutes` null (off) or an integer from 1 to 120. UI choices are 3, 5, 10, 15 or 20 minutes. It uses today's recorded UTC active time, never a streak, penalty or notification. This preference stays local and account scoped.

Focused verification: `tests/library-report.test.ts` and `tests/e2e/library-report.spec.ts`. Browser checks cover queue persistence/preparation, completion/saved filters, account separation, report evidence/goal persistence, real morphology against trusted public discovery fixtures, cold-start abstention, missing-provider fallback and mobile width.
