## Purpose

This document is a durable checkpoint for an end-to-end UX audit of the deployed Shadowing application. It is intentionally updated throughout the audit so the investigation can be resumed without losing context.

The audit covers:
- Live UI/interactivity across the app
- Practice/studio-mode workflows
- Dictionary, words/flashcards, progress and account flows
- Navigation and information architecture
- Visual consistency, responsive behaviour and accessibility issues
- Relevant implementation constraints found in the repository
- Competitor patterns where they materially improve the recommended experience

No application code is changed by this pull request. This branch is documentation-only.

## Initial user-reported issues to validate and refine

### Flashcards / Dictionary
- Add a **per-card furigana visibility control**, independent of the global reading preference.
- When **Open section** is used from a card, play the source clip **inline in the card/review surface** rather than forcing a context switch. The inline player must be minimisable/collapsible.
- Increase visual separation between **Play in context** and the **source-video/source-section metadata** so the primary action does not visually merge with provenance information.
- Replace the current review flow with an **Anki-style spaced-repetition interaction model**:
  - Present explicit interval previews beside each answer action, e.g. **Again · 1m**, **Hard · 6m**, **Good · 10m**, **Easy · 3d**.
  - Treat cards due later on the same calendar day as part of **today's review queue**, with learning/relearning steps handled within the session rather than requiring manual card selection.
  - Reviews should start from a due queue; users should not have to manually select individual cards to review.
- Clarify or rename **Inbox**. The current meaning and expected user action are not self-evident.
- Clarify the purpose of **tags**, expose where tags are created/edited, and show how they affect browsing/filtering.
- Introduce a first-class **deck model**:
  - Dedicated deck list/view.
  - Browse cards by deck.
  - Start today's review for a specific deck.
  - Configure new/review limits per deck and globally.
- Add a consistent **Back/Home navigation affordance** on Dictionary and Words/Flashcards screens.

### Progress
- Audit pending.

### Account
- Add a consistent **Back/Home navigation affordance**.
- Remove or significantly reduce the prominence of **manual sync**. Sync should be automatic by default and manual sync should be a recovery/diagnostic action, not a routine workflow.
- The page is under-utilised. Either:
  - convert account/settings into a side panel/modal for lightweight settings, or
  - make the full page useful with profile, subscription, learning preferences, sync status, data/export and account actions.

### Main practice / video page
- Studio mode is broadly useful, but the **token/word selection model is too fragmentary**. For example, hovering/selecting `話せます` may select only `話`, causing dictionary lookup to miss the meaningful inflected expression.
- Rework word selection to support **linguistically meaningful Japanese spans** (surface form + lemma/inflection awareness), with an easy way to expand/shrink the selected span.
- Reorganise the controls below the main practice area. The current studio-mode control layout lacks a clear hierarchy and feels visually fragmented.
- Fix **theme inconsistencies**: some studio-mode surfaces remain white in dark mode and some states create white text on white/light controls.
- In particular, the dictionary popover/side-panel result shown after selecting a word must inherit the active theme and meet contrast requirements.
