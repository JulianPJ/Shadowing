# Adaptive immersion (Phase B)

Hibiki keeps the shadowing loop central. A word lookup now starts with lexical data, while four explicit word states accumulate across lessons. The Word Browser at `/words` supports individual and bounded-page bulk edits, local recent-transcript vocabulary, dictionary search and source links. The practice coverage panel offers short lines with one Unknown word, or an Unknown word recurring in the same lesson. These features are Free; no model is asked to infer what the learner knows.

## Lexical data and licensing

The complete English JMdict snapshot of 5 October 2026 contains 218,863 entries. It is converted by [scriptin/jmdict-simplified](https://github.com/scriptin/jmdict-simplified), then compacted and split by Hibiki into 256 term-index and 256 entry shards. Readings, orthography restrictions, part of speech, multiple senses, register/domain tags and commonness flags are retained. 100,335,250 uncompressed bytes of static assets are generated; the largest shard is 375,494 bytes. Lookup loads the required same-origin shards, with a bounded 24-shard memory cache, rather than shipping the dataset in client or Worker code. This is a real general-purpose dictionary, including uncommon vocabulary, not a demo word list.

The dictionary is copyright James William Breen and the Electronic Dictionary Research and Development Group, distributed under [CC BY-SA 4.0](https://www.edrdg.org/edrdg/licence.html). Derived dictionary shards retain that licence. Attribution, source and licence links appear with every lexical result; `/lexicon/NOTICE.txt` supplies an additional notice. The code remains under its existing licence. Dictionary commonness is labelled as a JMdict marker, not a corpus rank or JLPT level. No native dictionary audio or external example corpus is redistributed; the actual media section supplies the sentence example and its existing source replay.

`scripts/lexicon-source.json` pins the upstream release URL and SHA-256. `npm run lexicon:prepare` verifies the archive checksum before producing assets, and build/development prehooks prepare both lexical and morphology assets. Generated assets/cache are ignored by Git. A fresh build needs network access to the pinned 11.5 MB archive; subsequent local builds reuse the verified cache. Preparation rejects a common-only or incomplete source. The procedure for updating is `npm run lexicon:update`, review the new source pin and dataset counts, then build/test and deploy. Run this at least monthly to satisfy EDRDG's update policy. The source snapshot is deliberately pinned so ordinary builds remain reproducible.

Kuromoji/IPADIC supplies contextual basic forms, POS and kana deterministically in the existing lazy worker. Inflected verb/adjective selections also use morphological auxiliary chains; no hand-written suffix guessing replaces morphology. Reading-specific dictionary senses and spelling restrictions are respected. Ambiguous readings, proper names, tokenization, compounds and new slang remain imperfect. A match shows available senses and allows the learner to choose a gloss; it does not assert which sense a speaker intended. Sentence translation stays a separate contextual fallback. Missing lexical entries can use the existing translation fallback for signed-in learners, or an authored gloss. Playback and manual entry survive lexical asset failure.

## Knowledge and account boundaries

`knowledge:records` stores one explicit `{lemma, reading, state, updatedAt}` per lexical basic form; states are Unknown, Learning, Known and Ignored. Unknown/unmarked have the same counting behaviour, but an explicit reset is retained as a timestamped record so older remote writes cannot resurrect a Known state. Saving vocabulary and SRS grading do not change knowledge automatically. A lemma-level state currently groups homographs/senses and does not unify unrelated kanji/kana spelling variants; the interface avoids claiming sense mastery.

Anonymous states stay in the anonymous namespace. Account states and their durable outbox use `hibiki:v1:account:<id>:knowledge:*`; no namespace is authentication proof. The dedicated `/api/knowledge` endpoint uses the existing session, verified-email, origin and account-header guards. Native D1 migration `0009_word_knowledge.sql` enforces a `(user_id, lemma)` primary key, allowed states, and account-deletion cascade. Writes are bounded to 100 records; reads page through 250 terms. Last update wins, with deterministic equal-date state/reading ordering shared by browser and SQL. Invalid/future client mutations are rejected. Local writes stay useful offline, and resend idempotently on authenticated hydration/focus/online. In-flight results are discarded after an account switch. The existing first-sign-in prompt includes word states only after explicit import consent.

The Word Browser renders at most 100 rows and bulk selects explicitly visible pages. It combines tracked states, available saved-word cache material and requested recent lesson analysis; it does not silently traverse the entire account dictionary. Saved dictionary export retains the full export traversal contract. Transcript state subscriptions share one external-store snapshot/listener set, avoiding an account-store parse for every displayed token.

## Coverage and useful lines

Coverage counts content-word **occurrences**, not characters or comprehension: nouns, verbs, adjectives, adverbs, adnominals and interjections, excluding numbers, dependent forms, suffixes, particles, auxiliaries and punctuation. Known alone counts as Known; Learning remains separate; Ignored occurrences leave the denominator. Unmarked words count Unknown. Canonical token reconstruction is checked for each section, and a whole-lesson percentage is withheld unless every section was analysed. No historical knowledge is fabricated from scores or browsing.

On a fresh profile, an explicit `Analyse my vocabulary` action loads the optional 18 MB Kuromoji dictionary. Profiles with states reuse it to highlight lexical forms across transcripts. Furigana remains separately controlled and defaults off. Derived morphology is bounded, cached and never attached to saved transcripts or shared content.

One-unknown recommendations require exactly one distinct Unknown lemma, at least one Known occurrence, no Learning words, and a short clean section: 2–12 seconds, at most 80 Japanese characters, at least two content occurrences, and non-estimated timing. High-value lines require one to three distinct Unknown lemmas, at least half the content occurrences Known, and an Unknown lemma that recurs at least twice in this lesson. This is local contextual usefulness, not a global frequency ranking. Both lists explain the target word, preserve exact-section replay and can filter the transcript. Incomplete analysis can still expose verified individual lines without publishing a misleading overall coverage score.

## Verification

`tests/adaptive-immersion.test.ts` covers native SQLite/D1-compatible ownership, cascade, pagination, stale conflict writes, endpoint limits, explicit local account scope, lexical inflection and restricted senses, occurrence coverage, incomplete analysis and recommendation timing. `tests/e2e/adaptive-immersion.spec.ts` exercises the actual lazy morphology/full lexical assets, anonymous persistence, cross-video highlighting, bulk status, recommendation filtering and account offline replay. Run against both the standard production server and the built Cloudflare preview.
